# КУМИТЭ — генератор турнирных сеток

Локальный веб-сервис для турниров по карате киокушинкай: Java 17+, Spring Boot 3.5, PostgreSQL 17, Flyway, HTML/CSS/JavaScript. Интерфейс на русском, без сборки Node.js.

## Запуск уже подготовленного проекта на этом компьютере

Запустите `start-local.cmd` и откройте http://localhost:8080. В подготовленной локальной копии исполняемый JAR уже собран в `target`; после клонирования выполните `mvn package`. Каталоги `target`, `.tools` и `data`, а также локальная `.env` в репозиторий не включены. В `.tools/postgres` находятся переносимые бинарные файлы PostgreSQL 17.6 из Maven Central (io.zonky.test.postgres); база проекта хранится в `data/postgres`, адрес `127.0.0.1:55432`. Установка системной службы не выполнялась. Перед запуском закройте ранее запущенный экземпляр приложения на порту 8080. Для остановки базы после закрытия приложения используйте `stop-db.cmd`.

## Быстрый запуск с PostgreSQL

Требуется работающий Docker Desktop (Linux containers). После клонирования скопируйте `.env.example` в `.env` и задайте `DB_PASSWORD`. `.env`, база, заявки и локальные инструменты в Git не включаются. Откройте PowerShell:

```powershell
cd C:\programs\kyokushin-brackets
Copy-Item .env.example .env
# Укажите свой пароль в .env перед первым запуском.
docker compose up --build -d
```

Откройте http://localhost:8080. Или запустите `start-postgres.cmd`.
База хранится в Docker volume `postgres_data`; `docker compose down` сохраняет её. Проверка логов: `docker compose logs -f app`.

## Деморежим без PostgreSQL

Требуются JDK 17+ и Maven 3.6.3+:

```powershell
cd C:\programs\kyokushin-brackets
mvn spring-boot:run -Dspring-boot.run.profiles=demo
```

Или `start-demo.cmd`. Используется отдельная файловая H2-база `data/demo`, данные сохраняются между запусками. Кнопка «Попробовать на демоданных» создаёт отдельный демонстрационный турнир с 16 участниками. Демоданные не добавляются без нажатия кнопки.

## Заявки команд DOCX

Откройте «Заявки» → «Загрузить заявку DOCX». Укажите команду, выберите документ и нажмите «Распознать участников». Поддерживается таблица из предоставленного образца: пол, ФИО, дата рождения, разряд, Кю, точный вес, ФИО тренера. Обозначения пола М, Ж и Д, а также веса с запятой поддерживаются. Подписи и медицинские визы не интерпретируются как допуск к соревнованиям.

Предпросмотр ничего не записывает в базу. Можно исправить строки и повторно проверить их. Для подтверждения отметьте подходящих участников. Добавление выполняется одной транзакцией; история заявки, тренер, разряд и исходный Кю сохраняются. Повторная загрузка не создаёт дубликаты по ФИО, дате рождения и полу. До импорта создайте категории по регламенту турнира. Строки без категории, с ошибками или дубликатами не принимаются. При загрузке заявку проверяет организатор; отдельной публичной формы отправки нет.

После жеребьёвки приём участников заблокирован. Загрузки ограничены DOCX размером до 10 МБ и 500 строками. XML не обращается к внешним ресурсам; исходный файл в базе не хранится.

Кю преобразуется в цвет пояса: 0 и 11 — белый, 10–9 — оранжевый, 8–7 — синий, 6–5 — жёлтый, 4–3 — зелёный, 2–1 — коричневый. Если нужен другой цвет, выберите его в предпросмотре (исходное Кю при ручной смене пояса очищается). Исходные значения видны до подтверждения.

## Пули по образцу

Экран и PDF используют вертикальную A4-пулю с согласованной шапкой с фотографии, линиями, номерами боёв, тренером под ФИО, таблицей мест и пустыми подписями. «Настройки пуль» позволяют сохранить татами, смену, ФИО главного судьи и секретаря. Оттиски печатей и чужие подписи не воспроизводятся. Качество логотипов ограничено исходной фотографией.

При 4 участниках и при 16 и более предусмотрен отдельный бой за третье место. При 3 участниках бронзовый узел получает единственного проигравшего полуфинала автоматически, без фиктивного соперника. При 5–15 участниках — два третьих места. При 1–2 участниках третье место не присуждается. Новое правило добавляет необходимый бронзовый узел в существующие сетки, сохраняя предыдущие результаты.

## Работа

1. Создайте турнир: название, дата и место.
2. Добавьте категории по регламенту: пол, возраст, вес, диапазон поясов.
3. Зарегистрируйте спортсменов. Возраст определяется на дату турнира, а не на текущий день. Фильтр «Без категории» показывает тех, кому требуется подходящая категория.
4. Проведите жеребьёвку. Состав и категории блокируются. Любой участник без категории блокирует жеребьёвку, поэтому никто не пропадает из сеток.
5. Выберите категорию в разделе «Сетки». Нажмите на победителя боя и подтвердите результат. Победитель автоматически переходит дальше. Свободные проходы обрабатываются автоматически.
6. Выгрузите сетки в CSV (UTF-8 с BOM, разделитель `;`) или нажмите «Печать / PDF»: скачается PDF выбранной категории на A4 в книжной ориентации. Откройте файл в просмотрщике PDF и распечатайте. Сначала необходимо провести жеребьёвку; для пустой сетки выводится пояснение. Сетки свыше 16 мест разбиваются на блоки по 16 мест и отдельный лист объединяющих раундов. Призовые места и бронзовый бой располагаются под сеткой на том же листе.

### Правила распределения

- Возраст: обе границы включены (например, 12–13 лет).
- Вес: нижняя граница исключена, верхняя включена: `(0;45]`, `(45;500]`. В открытой весовой категории укажите верхнюю техническую границу 500 кг.
- Пояса: белый → оранжевый → синий → жёлтый → зелёный → коричневый → чёрный. Обе границы включены. Кю и даны внутри цвета не разделяются.
- Мужские и женские категории разделены. Категории с пересекающимися условиями запрещены.
- Регламент федерации не встроен: организатор задаёт и проверяет категории самостоятельно. Автоматического объединения возрастов или весов нет.
- Разведение команд: название клуба сравнивается без учёта регистра и повторных пробелов. Пустой клуб не считается общей командой. На каждом уровне сетки число одноклубников распределяется максимально равномерно: двое по разным половинам, четверо по четвертям. При избытке одноклубников ранние встречи могут быть неизбежны. Остальные решения случайные и воспроизводимы по seed. Сохраняется баланс свободных проходов.
-  размер сетки — ближайшая степень двойки. Свободные проходы распределяются по стандартному порядку посева. Один участник автоматически становится победителем категории; нулевая категория остаётся без сетки.
- Призовые места: 1-е — победитель финала, 2-е — проигравший финала. Правила третьего места приведены в разделе «Пули по образцу». Рейтинговый посев и утешительные бои не реализованы.
- Призёры отображаются над сеткой, включаются в печать и доступны отдельным CSV. Бронзовый бой отображается под основной сеткой. При обновлении существующие результаты сохраняются, для старых категорий с 3, 4 или от 16 участников добавляется недостающий бронзовый бой. Для применения нового разведения команд требуется новая жеребьёвка; результаты при этом не сбрасываются автоматически.
- Результат нельзя изменить по одному бою: для исправления используйте «Сбросить» (удаляет все сетки и результаты турнира с подтверждением), затем проведите жеребьёвку заново.
- Seed сохраняется в базе. Через API можно повторить жеребьёвку с тем же `seed` после сброса при неизменном составе и порядке категорий.

## Сборка и тесты

```powershell
mvn test
mvn package
java -jar target/brackets-1.0.0.jar --spring.profiles.active=demo
```

Тесты используют H2 в PostgreSQL-режиме и ту же Flyway-миграцию. Они проверяют границы категорий, возраст, разделение по полу и поясу, сетки на 1–33 участника, проходы, полный турнир, воспроизводимость, ограничения результатов и CSV. Дополнительно выполнена проверка запуска, миграции и полного цикла через HTTP с настоящим PostgreSQL 17.6.

## Подключение к своей PostgreSQL

Создайте базу и пользователя, затем задайте переменные окружения `DB_URL`, `DB_USER`, `DB_PASSWORD` и выполните `mvn spring-boot:run` без профиля demo. Значения по умолчанию находятся в `application.yml`. Flyway создаёт схему, Hibernate проверяет её. В Compose пароль можно переопределить переменной `DB_PASSWORD` перед первым запуском базы. Изменение переменной не меняет пароль уже созданного пользователя PostgreSQL.

## REST API

Все пути начинаются с `/api/tournaments`:

| Метод | Путь | Действие |
|---|---|---|
| GET / POST | `/` | Список / создание турнира |
| GET | `/{id}` | Турнир, категории, участники, бои, распределение |
| POST | `/{id}/categories` | Создание категории |
| DELETE | `/{id}/categories/{cid}` | Удаление категории до жеребьёвки |
| POST | `/{id}/athletes` | Регистрация участника |
| DELETE | `/{id}/athletes/{aid}` | Удаление участника до жеребьёвки |
| POST | `/{id}/draw` | Жеребьёвка: `{}` или `{"seed":42}` |
| DELETE | `/{id}/draw` | Сброс всех сеток и результатов |
| POST | `/{id}/bouts/{bid}/winner` | Победитель: `{"athleteId":1}` |
| GET | `/{id}/export` | CSV всех сеток турнира, включая бронзовые бои |
| GET | `/{id}/podium/export` | CSV призёров турнира |
| GET | `/{id}/categories/{cid}/print.pdf` | PDF выбранной категории, без изменения жеребьёвки |
| POST | `/demo` | Создание нового демотурнира |

Примеры полей JSON — в `Inputs.java`. Мутации сериализуются блокировкой строки турнира, результаты и сетки сохраняются одной транзакцией.

## Границы использования

Приложение рассчитано на локальную работу организатора, поэтому доступ привязан к 127.0.0.1 и аутентификации нет. Перед публикацией в сеть нужны учётные записи, разграничение доступа и HTTPS. Пароль задаётся через локальную `.env` или переменные окружения и не хранится в исходниках. Резервное копирование PostgreSQL делайте штатным `pg_dump`; персональные данные храните согласно правилам вашей организации.

Официальные требования Spring Boot: https://docs.spring.io/spring-boot/3.5/system-requirements.html


Новые API: `POST /api/tournaments/{id}/applications/preview` (multipart: `file`, `team`), `POST /applications/check`, `POST /applications`, `GET /applications`, `GET/PUT /print-settings` — все относительно `/api/tournaments/{id}`. Проверка и подтверждение используют список `entries`; категории определяются повторно на сервере.


Свободный проход не отображается как отдельный поединок: спортсмен сразу стоит на входе следующего раунда на экране и в PDF. Автоматические узлы остаются внутренними для сохранения структуры и существующих результатов, но исключаются из карточек боёв и CSV. Выбирать победителя свободного прохода не требуется. Автоматическое третье место при трёх участниках также не рисуется как фиктивный бой.
